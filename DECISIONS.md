# Decisions

Choices the spec left open, and why. Newest context: November 2026.

## Tooling & versions

- **npm, not pnpm.** npm ships with Node and cPanel's Node environment, so the server's
  `npm ci --omit=dev` uses the same lockfile format as development.
- **Three separate npm projects, not workspaces.** Root (lint/format tooling + scripts),
  `site/` and `api/`. With workspaces there is only a root lockfile, but the API is deployed on
  its own and needs `api/package-lock.json` for `npm ci` on the server.
- **Shared GitHub logic lives in `shared/github/`** (plain TypeScript, no dependencies). The
  site imports it in the build script and components; the API bundles it via esbuild. One
  filter implementation, tested once.
- **Node 22 everywhere.** Astro 7 (latest stable) requires Node ≥ 22.12, and the server's cPanel
  Node.js app runs Node 22 (venv `/home/lazyjapy/nodevenv/api/22`). CI, `.nvmrc`, the API's
  esbuild target (`node22`), `engines` and `@types/node` all match.
- **The API is bundled with esbuild** into `dist/app.js` + `dist/sync.js` (CommonJS, deps
  external). `tsc --noEmit` does type-checking. `dist/` (bundles + `package.json` + lockfile)
  is exactly what gets rsynced, so `app.js` sits at the API root as Passenger expects.
- **TypeScript 6.0**, not 7.0: `typescript-eslint` and `@astrojs/check` don't support TS 7 yet.
- **Vitest pinned to 4.0.x**: Vitest 4.1/5 hit an npm 10/11 install bug (`Cannot read
  properties of null (reading 'edgesOut')`) on the development machine.
- **ESLint 9 flat config** at the root covers both projects (`eslint-plugin-astro`,
  `typescript-eslint`, React hooks rules). Prettier with `prettier-plugin-astro`.
- `@emnapi/core`/`@emnapi/runtime` are site dev dependencies so `astro check` works on
  Windows ARM64 (no native binary there; it falls back to WASM).
- **No `cors` / `dotenv` packages.** CORS is ~25 lines (`api/src/lib/http.ts`) and `.env` loading
  ~30 (`api/src/env.ts`). The API's runtime deps are exactly: express, helmet, zod,
  nodemailer, mysql2.

## Design system

- **Palette: "ink + vermilion".** Dark-first ink background (`#0c0e12`), warm off-white text
  (`#ecebe6`), one strong accent: **vermilion `#ff5a36`**, the color of torii gates and
  hanko seals. It nods to "ninja" without costume clichés and reads confident and a little
  playful. Light mode uses paper `#f7f5f0` and a deeper vermilion `#c2341a` so accent text
  stays AA.
  - Contrast (WCAG): text on bg ≈ 16:1 (dark) / 16:1 (light); muted ≈ 7.4:1 / 6.4:1;
    accent ≈ 6.3:1 on dark bg; light accent ≈ 5.1:1 on paper. Status colors (shipped green,
    building amber, personal blue) are ≥ 4.5:1 in both themes.
  - Tokens live in `site/src/styles/global.css` under `@theme` (raw palette: `ink-*`,
    `paper-*`, `vermilion-*`) and `@theme inline` (semantic, theme-aware: `bg`, `surface`,
    `surface-2`, `border`, `fg`, `muted`, `accent`, `accent-strong`, `accent-ink`,
    `accent-soft`, `shipped`, `building`, `personal`). Use `bg-bg`, `text-muted`,
    `border-border`, `text-accent`, etc.
- **Type pair: Bricolage Grotesque (display) + Inter (text)**, JetBrains Mono for code/meta.
  Bricolage has quirky, slightly condensed grotesque shapes that give headlines personality;
  Inter keeps body text calm and legible. Self-hosted variable fonts (Latin subset) through
  **Astro's Fonts API**, which generates metric-matched fallbacks. That removed a 0.12 CLS
  caused by the hero heading re-wrapping on font swap.
- **Source badges:** LazyNinja = solid vermilion pill with a small shuriken; Personal =
  dashed blue outline (cards for personal repos also get a dashed border). They differ in
  shape and color, not color alone.
- **Hero:** giant outlined "Lazy" + solid "Ninja." wordmark, a floating sleepy-ninja mark with
  a slow shuriken and drifting "z"s. All motion is `motion-safe:` only, and a global
  `prefers-reduced-motion` rule kills remaining animations/transitions.
- **Logo:** a rounded ink square with a vermilion headband and half-closed "lazy" eyes
  (`site/public/favicon.svg`). Favicon set (ICO 16/32/48, SVG, 180/192/512 PNG, maskable)
  generated by `npm run assets --prefix site`.
- **Open Graph images are generated per page at build time** with Satori → sharp (sharp is
  already an Astro dependency). Cheap (~60 ms/image), so every page and post gets its own.

## Site behavior

- **Clean URLs:** `build.format: "file"` + `trailingSlash: "never"` → `about.html` served at
  `/about`. `.htaccess` redirects `*.html`, `/index.html` and trailing slashes to the clean
  form with a 301, and `DirectorySlash Off` stops `/blog` (both `blog.html` and `blog/`) being
  redirected to `/blog/`. Canonicals, sitemap and RSS links use the same clean form.
- **`.htaccess` source of truth** is `deploy/public_html.htaccess`, and `site/public/.htaccess`
  is an exact copy (CI fails if they differ).
- **Strict CSP without `'unsafe-inline'` scripts:** `site/scripts/postbuild.mjs` hashes every
  inline script in the built HTML (theme init, Astro island bootstrap) and writes the hashes
  into `dist/.htaccess`. Styles allow `'unsafe-inline'` (Astro inlines CSS and font-face
  rules; low risk). Verified in a browser: no CSP violations.
- **CSS is inlined** (`inlineStylesheets: "always"`) to remove the render-blocking stylesheet
  request (~10 KB gzipped, mostly the typography plugin), which was the main Lighthouse cost.
- **Theme:** an inline head script applies the saved choice, else the system preference, else
  dark, before first paint. The toggle (React island, `client:idle`) saves to `localStorage`
  and follows system changes until the visitor picks.
- **Mobile nav** is a horizontally scrollable row, not a hamburger: no JS, always visible.
- **Drafts** show in `astro dev` and are hidden in production builds.
  `SHOW_DRAFTS=1` includes them in a local production build (used for the Lighthouse run below).
- **Home featured rows:** up to 3 LazyNinja projects (featured first, then most recent
  non-archived) and a separate, labeled row of up to 3 personal projects. Without any
  `lazyninja-featured` topics the rows still fill with recent work.
- **Build-time GitHub data is not committed** (`site/src/data/github.json` is generated). Local
  builds keep the previous snapshot if GitHub is unreachable; deploys run with
  `GITHUB_FETCH_STRICT=1` and fail instead of shipping an empty Projects page.
- **A daily scheduled deploy** rebuilds the site so build-time data (new repos, topics) stays
  fresh even without pushes. It only redeploys the site.
- **Profile README repos** excluded: `<login>/<login>` and the org `.github` repo.
- **About skills:** to avoid inventing facts, the only filled-in group is "Languages on
  GitHub", generated from public repos. Other groups are clearly marked placeholders.
- **/stats** is a static, `noindex` page outside the nav, disallowed in robots.txt, excluded
  from the sitemap and never tracked. The admin token lives in `sessionStorage` (this tab only).
  It shows 7/30-day totals, a single-series daily column chart with tooltips and a table view,
  and top pages/referrers.

## API behavior

- **GitHub cache:** one row per repo in `github_repo_cache` plus `sync_state.updated_at`.
  `GET /github/repos` never calls GitHub per request: fresh (< 6 h) cache is served as is.
  When stale, it serves the stale data immediately and refreshes in the background
  (deduplicated, 10-minute backoff after a failure). It blocks only when the cache is empty.
  Response includes `syncedAt` and `stale`.
- **Exclude pattern:** configurable in two places because they run in different places: site
  `GITHUB.excludePatterns` (build) and API `GITHUB_EXCLUDE_PATTERN` (optional env, defaults
  to the same course-code regex).
- **Contact:** order of checks is rate limit → zod validation → honeypot → 3-second minimum.
  The honeypot returns a fake `200 {ok:true}` so bots learn nothing. Mail is sent first, then
  the message is stored with `mail_status` (`sent`/`failed`/`skipped`). The request succeeds if
  either worked, so an SMTP outage never loses a message. Names may not contain newlines
  (header-injection guard).
- **Rate limit:** fixed 1-hour windows in MySQL (`rate_limits`), keyed by an HMAC of the IP
  (no raw IPs stored), atomic `INSERT … ON DUPLICATE KEY UPDATE`. Every POST counts, including
  invalid ones. Old windows are purged by `npm run sync`.
- **Analytics:** `visitor_hash = sha256(HMAC(secret, "analytics-salt:<UTC day>") | ip | ua)`,
  truncated to 32 hex chars. The daily salt is derived, never stored. "Unique visitors" for
  7/30 days is the **sum of daily uniques** (cross-day uniqueness is deliberately impossible).
  Bots (by UA) and DNT/GPC requests are dropped server-side too. The beacon uses
  `text/plain` so `sendBeacon` needs no CORS preflight.
- **Country** comes from common proxy headers (`CF-IPCountry`, …) when present. Namecheap
  shared hosting usually provides none, so it will mostly be `NULL`. That's expected.
- **`trust proxy` = 1** (`TRUST_PROXY` env to change): LiteSpeed sits in front of Passenger,
  so the client IP is the last `X-Forwarded-For` hop.
- **Errors:** JSON everywhere. Stack traces are logged and included in responses only outside
  production.
- **Production config is validated at startup** (zod). Missing DB/SMTP/token values, or
  secrets shorter than 24 characters, stop the app with a clear message in `stderr.log`.
- **Dev store:** without `DB_HOST` (outside production) the API uses an in-memory store and a
  console mailer, so `npm run dev` works with zero setup. `STORE=memory` is rejected in production.

## Deploy

- **SSL comes from acme.sh** (Let's Encrypt), not cPanel AutoSSL. `/.well-known/` is served before
  any redirect and is never deleted by deploys.
- **HSTS without `includeSubDomains`**: `mail.`, `webmail.` and other cPanel subdomains aren't
  on the site's certificate, so forcing HTTPS on every subdomain would break them.
- **SMTP via `premium149.web-hosting.com`**: the server hostname's certificate is valid, while
  `mail.lazyninja.co` is served the shared `*.web-hosting.com` certificate (a hostname mismatch
  that nodemailer rejects).

- **CI runs once per deploy:** `deploy.yml` calls `ci.yml` as a reusable workflow, and the
  deploy jobs download CI's build artifacts, so what was tested is what ships. `ci.yml`
  handles PRs and pushes to other branches itself.
- **Change detection** diffs `github.event.before..sha`. `shared/**` counts for both site and
  API. On a first push, a rewritten history or a manual run, everything deploys.
- **Extra rsync excludes** for the API beyond the spec (`public/`, `.htaccess`, `stderr.log`):
  cPanel/Passenger may create these in the app root, and `--delete` must not remove them.
- **Smoke test** retries 5× with 10 s gaps. The site check fails the run; the API check only warns.

## Lighthouse report

Measured locally on 2026-11-17 against a production build (`SHOW_DRAFTS=1` so the sample post
exists), Lighthouse 12 driving headless Edge, default throttling.

| Page                 | Mode    | Performance | Accessibility | Best practices | SEO |
| -------------------- | ------- | ----------- | ------------- | -------------- | --- |
| Home `/`             | Mobile  | 95          | 100           | 96             | 100 |
| Projects `/projects` | Mobile  | 95          | 100           | 96             | 100 |
| Post `/blog/hello-world` | Mobile | 96       | 100           | 96             | 100 |
| Home `/`             | Desktop | 100         | 100           | 96             | 100 |
| Projects `/projects` | Desktop | 100         | 100           | 96             | 100 |
| Post `/blog/hello-world` | Desktop | 100     | 100           | 96             | 100 |

Mobile: CLS 0 on all three, TBT ≤ 80 ms, LCP ≈ 2.6–2.7 s (simulated slow 4G).

**Best practices 96** is entirely one audit, "errors in console": the page-view beacon and
live-stats fetch fail with `ERR_NAME_NOT_RESOLVED` because `api.lazyninja.co` doesn't exist
yet. Once the API is live this clears. A separate run serving `dist/` with the real CSP header
showed no CSP violations.

Fixes made during measurement: inlined CSS (render-blocking request), Astro Fonts API with
metric-matched fallbacks (Projects CLS 0.116 → 0), and switching the Shiki themes to
`github-light-default` / `github-dark-default` (code-comment contrast failed AA with the
dimmed/older themes).
